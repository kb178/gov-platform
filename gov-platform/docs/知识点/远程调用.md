# 远程调用（Feign）



---

## 为什么需要远程调用

gov-approval（8083）和 gov-item（8082）是两个独立的程序，跑在不同端口。审批服务需要拿事项服务的数据（比如"这个事项要哪些材料"），就得跨服务通信。

最原始的做法是用 RestTemplate 手动发 HTTP 请求，拼 URL、发请求、解析 JSON，每个调用都要写一遍，很啰嗦。Feign 把这些封装了，让你像调本地方法一样调远程接口。

---

## Feign 怎么用

三个注解搞定：

```java
@FeignClient(value = "gov-item")           // 调哪个服务（从 Nacos 找地址）
public interface RemoteItemService {

    @GetMapping("/itemMaterialRelation/item/{itemId}")   // 调哪个接口
    R<List<Map<String, Object>>> getMaterialListByItemId(
        @PathVariable("itemId") Long itemId);            // 参数怎么传
}
```

这个接口没有实现类。Spring 启动时扫描到 `@FeignClient`，用动态代理生成一个实现类，注册到容器里。你 `@Autowired` 拿到的就是这个代理对象，调方法时它自动帮你发 HTTP、解析 JSON、返回对象。

启动类上要加 `@EnableFeignClients(basePackages = "com.haikou")` 开启扫描。

---

## 用的时候要注意什么

调远程接口不能假设对方一定正常。gov-item 可能没启动、可能挂了、可能很慢。所以调用的地方要包 try-catch 做降级：

```java
try {
    R<List<Map<String, Object>>> result = remoteItemService.getMaterialListByItemId(itemId);
    // 正常处理...
} catch (Exception e) {
    // 对方挂了，跳过这个校验，不阻塞主流程
    log.warn("调用 gov-item 失败，跳过校验: {}", e.getMessage());
}
```

还有一种情况是对方返回了，但业务上失败（比如 code 不是 200），也要判断一下 `result.isSuccess()`，不能拿到就用。

---

## 会遇到的问题

### 1. 对方挂了

请求发出去没响应，用户一直等着。要配超时时间，不能无限等：

```yaml
feign:
  client:
    config:
      default:
        connectTimeout: 3000   # 连接超时 3 秒
        readTimeout: 5000      # 读取超时 5 秒
```

超时了就走降级逻辑。

### 2. 对方响应慢，把自己拖垮

gov-item 查个数据要 3 秒，gov-approval 的线程就等 3 秒。1000 个请求同时进来，线程池全被占满，gov-approval 自己也瘫了。这叫连锁反应。

靠超时 + 熔断解决。熔断就像保险丝：对方连续失败到一定次数，就不再真的调了，直接返回降级结果，保护自己。过段时间再放一个请求试试，好了就恢复正常。

Sentinel 可以做这些事，项目里已经有这个依赖了。

### 3. 一边成功一边失败，数据不一致

gov-approval 把申请状态改成"已通过"，然后调 gov-message 发通知，结果通知没发出去。状态变了但用户不知道。

这种不适合用事务解决（跨服务没法用本地事务）。做法是发消息到 RabbitMQ，让 gov-message 自己去消费、自己去发通知。对方挂了消息就在队列里等着，起来了再处理。最终一致就行。

### 4. 重复调用

网络抖动导致超时，Feign 自动重试，但其实第一次已经调成功了。结果处理了两次。

要做幂等设计，比如带一个唯一请求 ID，第二次进来发现已经处理过就直接返回。

### 5. 服务雪崩

一个服务挂了，调它的服务跟着挂，然后调那个服务的也挂，整个系统全倒。

靠限流 + 熔断 + 降级三道防线。限流控制进入的流量，熔断断开不稳定的调用，降级给兜底结果。

---

## 总结

远程调用的核心问题是"不可靠"——对方可能挂、可能慢、可能重复。所以要有超时、熔断、降级、限流、幂等这几道防线。面试被问到，能说出问题和对应的解决思路就够了。

# Sentinel 使用笔记

限流、熔断、降级这些概念都懂了，这里记的是怎么在项目里用。

## 引依赖

pom 里加这个就行，项目已经有了：

```xml
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>
```

## 接 Sentinel 控制台

Sentinel 有个网页控制台，能在页面上动态配规则，不用改代码。

**第一步：下载启动控制台**

```bash
# 下载 sentinel-dashboard.jar，然后
java -Dserver.port=8858 -jar sentinel-dashboard.jar
```

访问 http://localhost:8858，账号密码都是 `sentinel`。

**第二步：项目里配置控制台地址**

```yaml
spring:
  cloud:
    sentinel:
      transport:
        dashboard: localhost:8858   # 控制台地址
        port: 8719                  # 项目和控制台通信的端口
```

启动项目后，控制台的"机器列表"里就能看到你的服务了。

## 代码里怎么写

### 方式一：@SentinelResource 注解（推荐）

最常用的方式，在方法上加注解，指定资源名和降级方法：

```java
@SentinelResource(
    value = "getMaterialList",              // 资源名（控制台用这个名字配规则）
    fallback = "getMaterialListFallback"    // 降级方法名
)
public R<List<Map<String, Object>>> getMaterialList(Long itemId) {
    return remoteItemService.getMaterialListByItemId(itemId);
}

// 降级方法：参数和原方法一样，多一个 Throwable
public R<List<Map<String, Object>>> getMaterialListFallback(Long itemId, Throwable e) {
    log.warn("查询材料清单降级: {}", e.getMessage());
    return R.ok(Collections.emptyList());
}
```

注意几点：
- `fallback` 处理的是所有异常（包括业务异常）
- 如果只想处理限流/熔断的异常，用 `blockHandler` 而不是 `fallback`
- 降级方法的返回值要和原方法一致
- 降级方法要在同一个类里（或者用 `blockHandlerClass` 指定类）

### 方式二：SphU 代码方式（不推荐，太啰嗦）

```java
Entry entry = null;
try {
    entry = SphU.entry("getMaterialList");
    // 正常业务逻辑
    return remoteItemService.getMaterialListByItemId(itemId);
} catch (BlockException e) {
    // 被限流/熔断了
    return R.fail("系统繁忙，请稍后再试");
} finally {
    if (entry != null) entry.exit();
}
```

一般不用这种方式，注解够了。

## 在控制台配规则

项目启动后，在控制台页面上配：

**限流规则（流控规则）：**
- 资源名：`getMaterialList`
- 阈值类型：QPS
- 单机阈值：100（每秒最多 100 个请求）
- 流控效果：快速失败（超出直接拒绝）

**熔断规则（降级规则）：**
- 资源名：`getMaterialList`
- 熔断策略：慢调用比例 / 异常比例 / 异常数
- 阈值：比如异常比例 > 50%
- 熔断时长：10 秒（熔断 10 秒后放一个请求试试）

**热点规则：**
- 针对某个参数限流，比如 `itemId=1001` 这个事项的查询每秒最多 50 次

## 对照到我们的项目

如果要给 gov-approval 调 gov-item 加上 Sentinel：

```java
@SentinelResource(value = "checkMaterial", fallback = "checkMaterialFallback")
private void checkMaterialCompleteness(ApplicationSubmitDTO dto) {
    R<List<Map<String, Object>>> result = remoteItemService.getMaterialListByItemId(dto.getItemId());
    // 校验逻辑...
}

private void checkMaterialFallback(ApplicationSubmitDTO dto, Throwable e) {
    log.warn("材料校验降级: {}", e.getMessage());
    // 降级：跳过校验，不阻塞提交
}
```

然后在控制台给 `checkMaterial` 这个资源配限流和熔断规则。

## 面试怎么说

"我用 Sentinel 做流量控制和熔断降级。限流对接口配了 QPS 阈值，超出直接拒绝。熔断方面，远程服务失败率超阈值时自动断开，快速失败防止雪崩。降级用 @SentinelResource 指定 fallback 方法，返回兜底数据。规则通过 Sentinel 控制台动态配置，不用改代码。"
