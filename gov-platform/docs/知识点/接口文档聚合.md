# 接口文档聚合（Spring Cloud Gateway + Swagger）

> 记录时间：2026-11-24
> 项目里网关聚合各服务接口文档的踩坑经验

---

## 为什么要在网关做聚合

微服务架构下每个服务都有自己的接口文档。gov-system 一个页面、gov-item 一个页面、gov-approval 一个页面……开发的时候切来切去很烦。网关聚合就是把所有服务的接口文档汇总到一个页面，一个入口看全部。

---

## 原理

每个服务引了 `knife4j-openapi3-jakarta-spring-boot-starter` 后，会自动暴露一个 `/v3/api-docs` 接口，返回该服务所有接口的 JSON 描述（OpenAPI 3 规范）。

网关聚合做的事就是：去各个服务拉这个 JSON，拼成一个页面展示。

```
浏览器 → 网关的 Swagger UI 页面
           ├── 拉 gov-system 的 /system/v3/api-docs
           ├── 拉 gov-item 的 /item/v3/api-docs
           ├── 拉 gov-approval 的 /approval/v3/api-docs
           └── 汇总展示，左上角下拉框切换服务
```

---

## 各服务怎么配

各服务引了 Knife4j starter 就行，不用额外配置。自动暴露 `/v3/api-docs`。

```xml
<!-- 各服务的 pom.xml -->
<dependency>
    <groupId>com.github.xiaoymin</groupId>
    <artifactId>knife4j-openapi3-jakarta-spring-boot-starter</artifactId>
</dependency>
```

如果想自定义文档标题、描述，加个配置类：

```java
@Configuration
public class Knife4jConfig {
    @Bean
    public OpenAPI customOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("系统服务接口文档")
                        .version("1.0.0")
                        .description("用户管理、角色管理、菜单管理等接口"));
    }
}
```

## 网关怎么配

网关的配置和普通服务不一样，因为 Spring Cloud Gateway 是 **WebFlux（响应式）架构**，不是普通的 Spring MVC。

### 1. 加依赖

```xml
<!-- gov-gateway/pom.xml -->
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webflux-ui</artifactId>
    <version>2.3.0</version>
</dependency>
```

注意：这里用的是 `springdoc-openapi-starter-webflux-ui`（WebFlux 版），不是 `knife4j-gateway-spring-boot-starter`。

### 2. 配置聚合

```yaml
# gov-gateway/application.yml
springdoc:
  swagger-ui:
    urls:
      - name: 系统服务
        url: /system/v3/api-docs
      - name: 事项服务
        url: /item/v3/api-docs
      - name: 审批服务
        url: /approval/v3/api-docs
```

每个 `url` 对应一个服务的 api-docs 地址，走网关路由转发到各服务。左上角的下拉框显示 `name`，点切换就加载对应服务的接口。

### 3. 配置静态资源映射

**这步不能少**，不然 Swagger UI 的页面、JS、CSS 全部 404。

```java
@Configuration
public class WebFluxConfig implements WebFluxConfigurer {
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/webjars/**")
                .addResourceLocations("classpath:/META-INF/resources/webjars/");
    }
}
```

为什么需要这个？普通 Spring MVC 项目会自动映射 webjar 的静态资源，但 WebFlux 不会。不加这个配置类，访问页面会报 `404 No static resource swagger-ui/index.html`。

### 4. 认证白名单放行

网关的 AuthFilter 会拦截请求验证 Token，但接口文档的请求不能拦。注意路径可能带服务名前缀（如 `/approval/v3/api-docs`），用 `contains` 匹配更保险：

```java
private boolean isWhiteList(String path) {
    if (path.contains("/v3/api-docs") || path.contains("/webjars")
            || path.contains("/swagger-resources") || path.contains("/doc.html")) {
        return true;
    }
    return WHITE_LIST.stream().anyMatch(path::startsWith);
}
```

## 访问地址

启动网关和任意几个服务后，浏览器打开：

```
http://localhost:8080/webjars/swagger-ui/index.html
```

页面左上角有个下拉框可以切换服务，右边直接填参数发请求调试。

## 踩过的坑

### 1. knife4j-gateway-spring-boot-starter 在 WebFlux 下不好使

一开始用的是 `knife4j-gateway-spring-boot-starter`（Knife4j 官方的网关聚合包），结果页面报"Knife4j文档请求异常"，JS 里报 `Unexpected end of JSON input`——UI 加载了但拉不到数据。

原因：Spring Cloud Gateway 是 WebFlux 架构，这个包对 WebFlux 支持不好。换 `springdoc-openapi-starter-webflux-ui` 就好了。

### 2. 静态资源 404

换了 springdoc 之后页面还是 404，报 `No static resource swagger-ui/index.html`。原因是 WebFlux 不会自动映射 webjar 静态资源，需要手动加 `WebFluxConfig` 配置类。

### 3. 白名单匹配不上

Knife4j 聚合请求的路径带服务名前缀（如 `/approval/v3/api-docs/default`），白名单里写的是 `/v3/api-docs/`，用 `startsWith` 匹配不上。改成 `contains` 就好了。

---

## 总结

| 事项 | 做法 |
|------|------|
| 各服务 | 引 knife4j-openapi3-jakarta-spring-boot-starter，自动暴露 /v3/api-docs |
| 网关依赖 | springdoc-openapi-starter-webflux-ui（不是 knife4j-gateway） |
| 网关配置 | springdoc.swagger-ui.urls 列出各服务的 api-docs 地址 |
| 静态资源 | 手动加 WebFluxConfig 映射 /webjars/** |
| 认证放行 | 白名单用 contains 匹配 /v3/api-docs、/webjars |
| 访问地址 | http://localhost:8080/webjars/swagger-ui/index.html |

---

## 常见问题

**Q：为什么不用 knife4j-gateway-spring-boot-starter？**
A：它是 Knife4j 官方的网关聚合包，但对 Spring Cloud Gateway 的 WebFlux 架构支持不好，页面报"文档请求异常"。springdoc-openapi-starter-webflux-ui 是 WebFlux 原生支持的，更稳。

**Q：各服务要改什么吗？**
A：不用。各服务已经引了 Knife4j starter，自动就有 /v3/api-docs 接口了，网关直接拉就行。

**Q：访问 doc.html 还是 webjars/swagger-ui/index.html？**
A：用 `http://localhost:8080/webjars/swagger-ui/index.html`。`/doc.html` 是 Knife4j 自己的页面，用 springdoc 聚合时不走那个地址。

**Q：新增了一个服务怎么加到聚合里？**
A：在网关的 `springdoc.swagger-ui.urls` 下加一条，写上服务名和 api-docs 地址就行。

**Q：为什么请求被 401 拦了？**
A：网关的 AuthFilter 白名单没放行接口文档路径。检查白名单是不是用 `contains` 匹配 `/v3/api-docs` 和 `/webjars`，不能用 `startsWith`（因为路径可能带服务名前缀）。
