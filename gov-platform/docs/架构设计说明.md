## 二、公共模块为什么要分层？

### 问题背景

最初设计时，`gov-common` 可以做成一个整体模块，所有公共代码放在一起。但这样会导致一个问题：**不同服务需要的能力不同，整体引入会造成依赖冗余**。

### 各服务需求分析

| 服务 | 需要 Redis | 需要 Security | 需要 MyBatis | 需要 Web |
|------|-----------|---------------|-------------|---------|
| gov-gateway | ✅ | ❌ | ❌ | ✅ |
| gov-system | ✅ | ✅ | ✅ | ✅ |
| gov-approval | ✅ | ✅ | ✅ | ✅ |
| gov-message | ✅ | ✅ | ✅ | ✅ |

### 设计决策

将公共模块拆分为4个子模块，每个模块职责单一：

```
gov-common-core     → 最基础的工具类、实体类（所有服务都需要）
gov-common-redis    → Redis 能力（需要缓存的服务引入）
gov-common-security → 安全认证能力（需要登录验证的服务引入）
gov-common-mybatis  → 数据库能力（需要访问数据库的服务引入）
```

### 依赖关系图

```
                    ┌─────────────────┐
                    │ gov-common-core │  ← 所有模块都依赖（基础）
                    └────────┬────────┘
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
        ▼                    ▼                    ▼
┌───────────────┐  ┌──────────────────┐  ┌───────────────┐
│ gov-common-   │  │ gov-common-      │  │ gov-common-   │
│ redis         │  │ security         │  │ mybatis       │
└───────┬───────┘  └────────┬─────────┘  └───────┬───────┘
        │                   │                    │
        │            ┌──────┴──────┐             │
        │            │             │             │
        ▼            ▼             ▼             ▼
   ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐
   │ gateway │  │ system  │  │ approval│  │ message │
   └─────────┘  └─────────┘  └─────────┘  └─────────┘
```

### 举例说明

**场景：网关服务只需要 Redis，不需要 MyBatis**

```xml
<!-- ❌ 如果公共模块是一个整体，会引入所有依赖 -->
<dependency>
    <groupId>com.haikou</groupId>
    <artifactId>gov-common</artifactId>
</dependency>
<!-- 结果：引入了 MyBatis、Security、MySQL 驱动... 全部不需要 -->

<!-- ✅ 分模块后，只依赖需要的 -->
<dependency>
    <groupId>com.haikou</groupId>
    <artifactId>gov-common-redis</artifactId>
</dependency>
<!-- 结果：只引入 Redis 相关依赖，干净轻量 -->
```

### 优点总结

| 优点 | 说明 |
|------|------|
| **按需引入** | 每个服务只依赖需要的模块，避免引入不必要的依赖 |
| **启动更快** | 依赖少 → 类加载少 → 启动速度快 |
| **包体积小** | 打包后的 jar 更小，部署更快 |
| **职责清晰** | 每个模块只负责一件事，易于维护 |
| **可选组合** | 新服务可以自由组合需要的能力 |

## 三、gov-common-core 模块设计

### 设计原则

`gov-common-core` 是最基础的公共模块，所有服务都会依赖它。设计时遵循以下原则：

1. **零外部依赖**（除 Spring Boot 基础）- 不引入额外框架
2. **高频复用** - 只放所有服务都会用到的内容
3. **稳定不变** - 核心定义一旦确定，很少修改

### 模块结构

```
gov-common-core/
├── constant/           ← 常量定义
│   └── CommonConstants.java
│
├── domain/             ← 领域对象
│   ├── R.java          ← 统一返回结果
│   ├── BaseEntity.java ← 实体基类
│   ├── LoginUser.java  ← 登录用户信息
│   └── PageQuery.java  ← 分页查询参数
│
├── enums/              ← 业务枚举
│   ├── UserType.java       ← 用户类型（老百姓/工作人员/管理员）
│   ├── ApprovalStatus.java ← 审批状态（草稿/待受理/审核中/通过/驳回...）
│   ├── ItemStatus.java     ← 事项状态（草稿/已发布/已下线）
│   ├── MessageType.java    ← 消息类型（系统/审批/证照/提醒）
│   ├── ErrorCode.java      ← 错误码定义
│   ├── Sex.java            ← 性别
│   ├── YesNo.java          ← 是否
│   ├── DelFlag.java        ← 删除标志
│   ├── IdType.java         ← ID生成策略
│   └── DataScope.java      ← 数据权限范围
│
├── exception/          ← 异常处理
│   ├── BusinessException.java
│   └── GlobalExceptionHandler.java
│
└── utils/              ← 工具类
    ├── JwtUtils.java       ← JWT工具
    ├── DateUtils.java      ← 日期工具
    ├── StringUtils.java    ← 字符串工具
    └── SecurityUtils.java  ← 安全工具
```

### 为什么要有枚举类？

**问题**：业务状态散落在各个服务中，定义不统一

```java
// ❌ 没有枚举时，状态码到处写
if (status == 1) { ... }
if (status == 2) { ... }

// ✅ 使用枚举，语义清晰
if (status == ApprovalStatus.APPROVED.getCode()) { ... }
```

**枚举类的价值**：

| 优点 | 说明 |
|------|------|
| **语义清晰** | 代码可读性好，一看就知道含义 |
| **集中管理** | 状态码统一定义，修改方便 |
| **编译检查** | 传错类型编译报错 |
| **易于扩展** | 枚举可以带方法和属性 |

### 为什么要有错误码枚举？

**统一错误码规范**：按模块划分，便于排查问题

```
1xxx - 通用错误
2xxx - 用户相关
3xxx - 权限相关
4xxx - 审批相关
5xxx - 事项相关
6xxx - 证照相关
7xxx - 文件相关
```

## 四、代码生成器使用说明

### 4.1 为什么需要代码生成器？

**问题**：每个表都要手动写 Entity、Mapper、Service、Controller，重复劳动

**解决**：使用 MyBatis-Plus 代码生成器，一键生成

### 4.2 使用步骤

**第一步：准备建表 SQL**

```sql
-- 示例：系统用户表
CREATE TABLE sys_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
    username VARCHAR(50) NOT NULL COMMENT '用户名',
    password VARCHAR(100) NOT NULL COMMENT '密码',
    nickname VARCHAR(50) COMMENT '昵称',
    phone VARCHAR(20) COMMENT '手机号',
    email VARCHAR(100) COMMENT '邮箱',
    user_type TINYINT DEFAULT 1 COMMENT '用户类型（1老百姓 2工作人员）',
    dept_id BIGINT COMMENT '部门ID',
    status TINYINT DEFAULT 0 COMMENT '状态（0正常 1停用）',
    del_flag TINYINT DEFAULT 0 COMMENT '删除标志（0存在 1删除）',
    create_by VARCHAR(50) COMMENT '创建者',
    create_time DATETIME COMMENT '创建时间',
    update_by VARCHAR(50) COMMENT '更新者',
    update_time DATETIME COMMENT '更新时间',
    remark VARCHAR(500) COMMENT '备注'
) ENGINE=InnoDB COMMENT='系统用户表';
```

**第二步：修改 CodeGenerator 配置**

打开 `gov-common-mybatis/src/main/java/.../generator/CodeGenerator.java`

```java
// 1. 修改数据库连接
private static final String DB_URL = "jdbc:mysql://localhost:3306/gov_system";
private static final String DB_USERNAME = "root";
private static final String DB_PASSWORD = "root";

// 2. 修改父包名
private static final String PARENT_PACKAGE = "com.haikou.government.system";

// 3. 修改要生成的表名
private static final String[] TABLES = {
    "sys_user",
    "sys_role",
    // ... 添加你的表
};

// 4. 修改输出路径（根据目标服务修改）
pathMap.put(OutputFile.entity, PROJECT_PATH + "/gov-system/src/main/java");
```

**第三步：运行 main 方法**

右键运行 `CodeGenerator.main()`，自动生成：

```
gov-system/src/main/java/com/haikou/government/system/
├── domain/
│   └── SysUser.java          ← 实体类
├── mapper/
│   └── SysUserMapper.java    ← Mapper接口
├── service/
│   ├── SysUserService.java   ← Service接口
│   └── impl/
│       └── SysUserServiceImpl.java  ← Service实现
└── controller/
    └── SysUserController.java      ← Controller

gov-system/src/main/resources/mapper/
└── SysUserMapper.xml         ← Mapper XML
```

### 5.1 ID 生成策略：雪花算法

**配置位置**：`application.yml`

```yaml
mybatis-plus:
  global-config:
    db-config:
      id-type: ASSIGN_ID  # 雪花算法生成ID
```

**什么是雪花算法？**

雪花算法（Snowflake）是 Twitter 开发的分布式 ID 生成算法，生成 64 位（19位数字）的全局唯一 ID。

**ID 结构**

```
2083525981070446593
```

| 部分 | 位数 | 说明 |
|------|------|------|
| 符号位 | 1位 | 固定为0 |
| 时间戳 | 41位 | 毫秒级，可用69年 |
| 数据中心ID | 5位 | 支持32个数据中心 |
| 工作节点ID | 5位 | 支持32个节点 |
| 序列号 | 12位 | 同一毫秒内生成4096个ID |

**为什么选择雪花算法？**

| 对比项 | 自增ID | UUID | 雪花算法 |
|--------|--------|------|----------|
| 全局唯一 | ❌ 分布式会冲突 | ✅ | ✅ |
| 有序性 | ✅ 递增 | ❌ 无序 | ✅ 趋势递增 |
| 性能 | ✅ 高 | ✅ 高 | ✅ 高（本地生成） |
| 可读性 | ✅ 短 | ❌ 太长 | ✅ 19位数字 |
| 索引友好 | ✅ | ❌ | ✅ |

**适用场景**：分布式系统、需要全局唯一ID、对性能要求高

### 5.2 ThreadLocal + 拦截器：请求上下文传递

**问题背景**

在业务代码中经常需要获取 `HttpServletRequest` 信息（如客户端IP、请求头），但直接在 Controller 获取再传递给 Service 会导致：
- Controller 职责不清晰（不该关心IP获取细节）
- Service 方法签名被污染（多出IP参数）
- 代码重复（多处需要IP时）

**解决方案：ThreadLocal + 拦截器**

```
请求进入
    ↓
拦截器 preHandle → HttpRequestHolder.set(request)  // 存入 ThreadLocal
    ↓
Controller → Service → 通过 HttpRequestHolder.getClientIp() 获取IP
    ↓
拦截器 afterCompletion → HttpRequestHolder.clear()  // 清理，防止内存泄漏
```

**核心代码**

```java
// 1. ThreadLocal 持有者
public class HttpRequestHolder {
    private static final ThreadLocal<HttpServletRequest> REQUEST_HOLDER = new ThreadLocal<>();

    public static void set(HttpServletRequest request) {
        REQUEST_HOLDER.set(request);
    }

    public static String getClientIp() {
        HttpServletRequest request = REQUEST_HOLDER.get();
        return IpUtils.getClientIp(request);
    }

    public static void clear() {
        REQUEST_HOLDER.remove();
    }
}

// 2. 拦截器
public class RequestInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, ...) {
        HttpRequestHolder.set(request);  // 进入前存入
        return true;
    }

    @Override
    public void afterCompletion(...) {
        HttpRequestHolder.clear();  // 结束后清理
    }
}

// 3. Service 直接使用
public LoginVO login(LoginDTO loginDTO) {
    String loginIp = HttpRequestHolder.getClientIp();  // 无需传参
    // ...
}
```

**为什么必须在 afterCompletion 中清理？**

| 原因 | 说明 |
|------|------|
| 内存泄漏 | 线程复用时，旧数据会一直存在 |
| 数据混乱 | 线程被其他请求复用时，读到旧数据 |

**适用场景**

- 多处需要获取请求信息（IP、用户信息、请求头）
- 想保持 Controller/Service 签名干净
- 中大型项目统一管理请求上下文

**注意事项**

| 场景 | 问题 | 解决方案 |
|------|------|---------|
| 异步方法（@Async） | ThreadLocal 失效 | 手动传递参数，或使用 InheritableThreadLocal |
| 线程池 | ThreadLocal 失效 | 使用 InheritableThreadLocal 或手动传递 |

### 5.3 Gateway 网关搭建

**Gateway 是什么？**

Gateway（网关）是所有请求的统一入口，负责路由转发、权限校验、跨域处理等。

**架构图**

```
前端请求
    ↓
Gateway:8080（统一入口）
    ├── Token 校验（AuthFilter）
    ├── 跨域处理（CorsConfig）
    └── 路由转发
         ├── /system/** → gov-system:8081
         ├── /item/**   → gov-item:8082
         └── /approval/** → gov-approval:8083
```

**核心组件**

| 组件 | 文件 | 作用 |
|------|------|------|
| 启动类 | GovGatewayApplication.java | 服务启动 |
| JWT过滤器 | AuthFilter.java | Token 校验 |
| 跨域配置 | CorsConfig.java | 解决跨域问题 |
| 路由配置 | application.yml | 路径转发规则 |

**路由配置说明**

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: gov-system           # 路由ID（唯一标识）
          uri: lb://gov-system     # 目标服务（从Nacos获取地址）
          predicates:
            - Path=/system/**      # 匹配条件（路径匹配）
          filters:
            - StripPrefix=1        # 过滤器（去掉第一个路径前缀）
```

**请求转发流程**

```
前端请求：GET http://localhost:8080/system/sysUser/login
                                    ↓
                              Gateway 匹配 /system/**
                                    ↓
                              StripPrefix=1 去掉 /system
                                    ↓
                              转发到：http://gov-system/sysUser/login
```

**JWT 过滤器（AuthFilter）**

```java
// 白名单路径（不需要 Token）
private static final List<String> WHITE_LIST = Arrays.asList(
    "/sysUser/sendCode",
    "/sysUser/register",
    "/sysUser/login",
    "/sysUser/smsLogin"
);

// 过滤逻辑
@Override
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
    // 1. 白名单直接放行
    // 2. 获取 Authorization 头中的 Token
    // 3. 校验 Token 是否过期
    // 4. 解析 Token 验证签名
    // 5. 将用户信息放入请求头传递给下游服务
}
```

**跨域配置（CorsConfig）**

```java
// 跨域问题：前端 http://localhost:5173 访问后端 http://localhost:8080
// 解决方案：在 Gateway 统一配置，不用每个微服务都写
CorsConfiguration config = new CorsConfiguration();
config.addAllowedOriginPattern("*");  // 允许所有来源
config.addAllowedMethod("*");         // 允许所有方法
config.setAllowCredentials(true);     // 允许携带 Cookie
```

**测试命令**

```bash
# 通过 Gateway 访问系统服务
curl http://localhost:8080/system/sysUser/login \
  -H "Content-Type: application/json" \
  -d '{"phone":"17689882201","password":"123456"}'

# 不带 Token 访问（应该返回 401）
curl http://localhost:8080/system/sysUser/list

# 带 Token 访问
curl http://localhost:8080/system/sysUser/list \
  -H "Authorization: Bearer <token>"
```

**Gateway 依赖说明**

```xml
<!-- Spring Cloud Gateway（响应式Web框架） -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway</artifactId>
</dependency>

<!-- Nacos 服务发现 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>

<!-- 负载均衡 -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>

<!-- JWT -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
</dependency>
```

**注意事项**

| 问题 | 说明 |
|------|------|
| Gateway 使用 WebFlux | 不是 Spring MVC，不能用 @Autowired 注入 HttpServletRequest |
| 响应式编程 | 使用 Mono/Flux，不是传统的 Servlet |
| 不能引入 spring-boot-starter-web | 会和 WebFlux 冲突 |

### 5.4 日志配置（Logback）

**为什么需要日志？**

| 作用 | 说明 |
|------|------|
| 开发调试 | 看程序运行到哪一步，变量值是什么 |
| 问题排查 | 出错时看错误原因、堆栈信息 |
| 安全审计 | 记录谁、什么时候、做了什么 |
| 性能监控 | 找出慢接口，优化性能 |

**日志级别**

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| ERROR | 程序异常、需要关注 | 数据库连接失败、保存数据失败 |
| WARN | 警告、不影响运行 | 登录失败、参数不合法 |
| INFO | 关键业务流程 | 用户登录成功、订单创建成功 |
| DEBUG | 调试信息 | 查询条件、请求参数 |

**配置文件位置**

```
gov-common-core/src/main/resources/logback-spring.xml
```

**为什么放在 gov-common-core？**
- 所有服务都依赖 core 模块
- 只需要配置一份，所有服务共享

**日志配置结构**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <!-- 1. 配置变量 -->
    <property name="LOG_PATH" value="${LOG_PATH:-./logs}"/>
    <property name="APP_NAME" value="${spring.application.name:-gov-platform}"/>
    <property name="LOG_PATTERN" value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%level] [%thread] %logger{36}:%line - %msg%n"/>

    <!-- 2. 控制台输出 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
        </encoder>
    </appender>
```

## 8. JWT 认证过滤器

### 8.1 什么是 JWT 认证过滤器

JWT 认证过滤器是 Spring Security 的一部分，负责：
1. 从请求头中获取 Token
2. 验证 Token 是否有效
3. 将用户信息存入 Security 上下文

### 8.2 执行流程

```
请求进入
    ↓
┌─────────────────────┐
│   JWT 认证过滤器     │  ← 验证 Token
│   (JwtAuthFilter)   │
└─────────────────────┘
    ↓
┌─────────────────────┐
│   Spring Security   │  ← 检查权限
│   (SecurityConfig)  │
└─────────────────────┘
    ↓
┌─────────────────────┐
│   Controller        │  ← 处理业务
└─────────────────────┘
```

### 8.3 代码实现

**JwtAuthFilter.java**

```java
@Slf4j
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    @Autowired
    private JwtUtils jwtUtils;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {

        // 1. 获取 Token
        String token = getTokenFromRequest(request);

        // 2. Token 为空，直接放行
        if (StringUtils.isBlank(token)) {
            filterChain.doFilter(request, response);
            return;
        }

        // 3. 验证 Token
        try {
            if (jwtUtils.isTokenExpired(token)) {
                log.warn("Token 已过期");
                filterChain.doFilter(request, response);
                return;
            }

            jwtUtils.parseToken(token);

            // 4. 获取用户信息
            Long userId = jwtUtils.getUserIdFromToken(token);
            String username = jwtUtils.getUsernameFromToken(token);

            // 5. 将用户信息存入 Security 上下文
            UsernamePasswordAuthenticationToken authentication =
                    new UsernamePasswordAuthenticationToken(username, null, new ArrayList<>());
            authentication.setDetails(userId);
            SecurityContextHolder.getContext().setAuthentication(authentication);

        } catch (Exception e) {
            log.error("Token 验证失败：{}", e.getMessage());
        }

        // 6. 继续执行过滤器链
        filterChain.doFilter(request, response);
    }

    private String getTokenFromRequest(HttpServletRequest request) {
        String authHeader = request.getHeader("Authorization");
        if (StringUtils.isNotBlank(authHeader) && authHeader.startsWith("Bearer ")) {
            return authHeader.substring(7);
        }
        return null;
    }

    public static Long getCurrentUserId() {
        UsernamePasswordAuthenticationToken authentication =
                (UsernamePasswordAuthenticationToken) SecurityContextHolder.getContext().getAuthentication();
        if (authentication != null && authentication.getDetails() instanceof Long) {
            return (Long) authentication.getDetails();
        }
        return null;
    }
}
```

**SecurityConfig.java 注册过滤器**

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Autowired
    private JwtAuthFilter jwtAuthFilter;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            // 添加 JWT 认证过滤器
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .authorizeHttpRequests(auth -> auth
                .requestMatchers(
                        "/sysUser/sendCode",
                        "/sysUser/register",
                        "/sysUser/login",
                        "/sysUser/smsLogin",
                        "/doc.html",
                        "/webjars/**",
                        "/swagger-resources/**",
                        "/v3/api-docs/**"
                ).permitAll()
                .anyRequest().authenticated()
            );
        return http.build();
    }
}
```
